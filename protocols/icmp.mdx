smoltcp supports both ICMPv4 and ICMPv6. Echo replies are generated automatically by the
stack. The ICMP socket type lets you send and receive ICMP messages directly — for example,
to implement ping-like functionality.

## Feature flag

```toml
[dependencies]
smoltcp = { version = "0.13.0", default-features = false, features = [
    "proto-ipv4",   # or proto-ipv6
    "socket-icmp",
] }
```

## Automatic echo replies

By default, smoltcp responds to ICMP Echo Request messages automatically — no socket code
required. This behavior is controlled by the `auto-icmp-echo-reply` feature, which is enabled
in the default feature set.

To disable automatic echo replies (for example, to handle them yourself via an ICMP socket):

```toml
smoltcp = { version = "0.13.0", default-features = false, features = [
    "proto-ipv4",
    "socket-icmp",
    # omit "auto-icmp-echo-reply" to disable automatic responses
] }
```

<Note>
ICMPv4 and ICMPv6 protocol unreachable messages received from the network are not forwarded
to upper layers. ICMPv4 parameter problem messages are not generated by smoltcp.
</Note>

## Protocol behavior

### ICMPv4

- Header checksum is generated and validated.
- Echo replies are generated in response to echo requests (when `auto-icmp-echo-reply` is enabled).
- ICMP sockets can listen for Port Unreachable messages, or for any ICMPv4 message matching
  a specific identifier value.

### ICMPv6

- Header checksum is generated and validated.
- Echo replies are generated in response to echo requests (when `auto-icmp-echo-reply` is enabled).
- Neighbor Advertisement messages are generated in response to Neighbor Solicitations (NDISC).
- Router Solicitation messages are generated when `proto-ipv6-slaac` is enabled.

## ICMP socket API

An ICMP socket (`icmp::Socket`) works like a raw channel for ICMP messages. You bind it to
an endpoint that determines which messages it receives.

### Binding

The `Endpoint` enum controls what the socket listens to:

| Variant | Description |
|---|---|
| `Endpoint::Ident(id)` | Receives ICMPv4/ICMPv6 messages with the given identifier (useful for echo request/reply matching) |
| `Endpoint::Udp(ep)` | Receives ICMP Port Unreachable messages for the given UDP port |
| `Endpoint::Tcp(ep)` | Receives ICMP Port Unreachable messages for the given TCP port |

```rust
use smoltcp::socket::icmp;

let rx_buffer = icmp::PacketBuffer::new(vec![icmp::PacketMetadata::EMPTY], vec![0u8; 256]);
let tx_buffer = icmp::PacketBuffer::new(vec![icmp::PacketMetadata::EMPTY], vec![0u8; 256]);
let socket = icmp::Socket::new(rx_buffer, tx_buffer);

let handle = socket_set.add(socket);

// Bind to ICMP identifier 0x42 (matches echo request/reply pairs)
let socket = socket_set.get_mut::<icmp::Socket>(handle);
socket.bind(icmp::Endpoint::Ident(0x42)).unwrap();
```

## Ping example pattern

The following pattern implements the core of a ping utility: send an ICMP Echo Request and
receive the Echo Reply.

```rust
use smoltcp::socket::icmp;
use smoltcp::wire::{Icmpv4Packet, Icmpv4Repr, IpAddress};

let socket = socket_set.get_mut::<icmp::Socket>(handle);

// Send an echo request
if socket.can_send() {
    let icmp_repr = Icmpv4Repr::EchoRequest {
        ident: 0x42,
        seq_no: seq,
        data: b"smoltcp ping",
    };

    let mut payload = vec![0u8; icmp_repr.buffer_len()];
    let mut packet = Icmpv4Packet::new_unchecked(&mut payload);
    icmp_repr.emit(&mut packet, &checksum_caps);

    let dest = IpAddress::v4(192, 168, 69, 100);
    socket.send_slice(&payload, dest).unwrap();
}

// Receive the echo reply
if socket.can_recv() {
    let mut buf = [0u8; 256];
    let (n, addr) = socket.recv_slice(&mut buf).unwrap();
    let packet = Icmpv4Packet::new_checked(&buf[..n]).unwrap();
    // Inspect packet.msg_type(), packet.echo_ident(), packet.echo_seq_no()
}
```

<Tip>
The first ping in a new session is typically lost because the ARP cache is empty. smoltcp
drops the ICMP packet and sends an ARP request instead. Subsequent packets succeed once the
hardware address is resolved.
</Tip>

## NDISC neighbor advertisements

smoltcp generates Neighbor Advertisement messages automatically in response to Neighbor
Solicitations — no ICMP socket is needed for this. The behavior is part of the IPv6 interface
processing and is always active when `proto-ipv6` is enabled.
